## 你应该立即做的事

#### 1. 停止一切写入，尽快关机

文件系统已经被强制只读，但这只是软件保护。在硬件彻底不认盘之前，你需要：
```bash
sudo poweroff
```

不要再尝试 `fsck`、`mount -o remount,rw` 或任何修复命令，那样只会加重硬盘负担，可能彻底刮花盘片（机械盘）或耗尽闪存寿命（固态盘）。

#### 2. 检查物理连接（断电后操作）

- 打开机箱，将 `/dev/sda` 的数据线和电源线**两端都重新插拔一次**（或换一根线、换一个 SATA 口）。
- 如果是 M.2 固态，取下后清理金手指再重新固定。
- 重新开机，进入 BIOS 看能否识别到该硬盘。如果能，尝试进入 Live USB 系统（如 Ubuntu 安装 U 盘），看能否只读挂载。

很多时候，**仅仅就是线松了**，重插后硬盘就能恢复正常。如果重插后故障依旧，那么盘本身损坏的可能性极大。

#### 3. 如果重新连接后，系统能识别但仍有错误

此时的**唯一目标**是备份数据，而不是修复硬盘：

- 用 Ubuntu Live USB 启动，**不要挂载**损坏的分区。
- 使用 `ddrescue` 制作整盘镜像：
  ```bash
	sudo ddrescue -f /dev/sda /mnt/backup/sda.img /mnt/backup/sda.log
  ```
	`ddrescue` 会跳过坏扇区，尽量读出所有能读的数据。之后你可以从这个镜像文件里安全地恢复文件，或者尝试修复镜像中的文件系统。
- 如果没有另外的备份盘，也可以尝试只读挂载后立刻复制最重要的小文件，但不要期望能完整读出。

#### 4. 什么时候才考虑修复？

**只有在你已经放弃数据，或者已经成功完整备份之后**，才可以尝试修复文件系统：
```bash
sudo umount /dev/sda1
sudo fsck -y /dev/sda1
```

但请注意，根据你日志中硬件错误（`DID_BAD_TARGET`）的严重程度，`fsck` 大概率会失败或在过程中卡死，甚至导致硬盘彻底不认。**数据重要的话，永远不要用这种方式做第一次尝试。**
